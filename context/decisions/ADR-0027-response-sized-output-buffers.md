# ADR-0027: Размер ответа определяет границы буферов

## Решение

Пользователь line/protocol session задаёт допустимый запрос и ответ. Размер внутренних очередей не является отдельной
настройкой API. Это относится и к workers соответствующего pool.

| Сценарий | Настройка ответа | Связанная внутренняя граница |
| --- | --- | --- |
| Line | `maxResponseLines` | Число непрочитанных stdout lines, включая пустые |
| Line | `maxResponseChars` | Суммарные символы непрочитанных lines и отдельно длина незавершённой line |
| Protocol | `maxResponseBytes` | Непрочитанные wire bytes каждой из двух очередей stdout/stderr |
| Protocol | `maxResponseChars` | Декодированный текст, ожидающий text reads |

Line limits считают содержимое без LF/CRLF. Один временный CR допускается сверх границы частичной строки до следующего
символа; одинокий CR при EOF является содержимым. Protocol byte budget считает весь wire format, включая headers и
delimiters, и суммирует bytes, прочитанные adapter-ом с обоих streams.

Превышение ответа при чтении или соответствующего буфера имеет один reason `RESPONSE_TOO_LARGE`. Stdout overflow
сразу завершает session. Protocol stderr сохраняет bounded failure marker и становится ошибкой только при чтении
adapter-ом: обычные diagnostics не обязаны быть частью ответа.

## Польза и граница

Увеличения response limit достаточно, чтобы один полностью допустимый ответ поместился до начала чтения. Пользователю
не нужно знать скорость pump и согласовывать ограничения нескольких стадий. Это не гарантия при произвольном
unsolicited output или нескольких непрочитанных ответах: transport не знает прикладного framing.

Response limit не является общим heap budget. Pending output, текущий response, decoder staging и диагностический
transcript имеют разных владельцев; каждый ограничен своим назначением. Transcript retention остаётся независимой
настройкой, поскольку определяет полезный объём диагностики, а не допустимый ответ.

## Альтернативы и компромиссы

Независимые queue и unfinished-line настройки позволяют потоково читать большой response через маленький backlog либо
допускать больше unsolicited output, чем один ответ. Для обычного request/response эта гибкость не оправдывает
необходимость согласовывать лимиты. Более узкие прикладные ограничения строки/поля принадлежат decoder/adapter.

Автоматическое увеличение очереди при сохранении прежних setters оставило бы неоднозначный приоритет и зависимость от
порядка вызовов Draft. Общая queue для stdout/stderr дала бы diagnostics возможность вытеснить ответ. Обе альтернативы
отвергнуты. Нового policy object, preset или общего memory budget не вводится.

## Проверка

Transport tests задерживают consumer до полной публикации допустимого ответа, включая объём выше стандартных defaults.
Отдельно проверяются пустые lines, CRLF на границе, незавершённая line, overflow stdout, отложенная ошибка stderr и
суммарный response budget. Process integration tests и внешние consumers подтверждают те же настройки публичного API.
